# Tai Wén account setup

The app keeps exam and vocabulary source content global. Only individual learning state is stored in Supabase. Guest learning works without Supabase configuration.

1. Create or select a Supabase project. Apply [20261013_user_progress.sql](migrations/20261013_user_progress.sql), then [20261106_account_sync.sql](migrations/20261106_account_sync.sql). All private tables use row-level security and restrict reads/writes to `auth.uid() = user_id`. The second migration adds conflict-safe progress revisions, profile preferences, personalized sets, and resumable test-attempt fields. Confirm both migrations appear in the project's migration history before enabling real accounts.
2. In Supabase Authentication → URL Configuration, set the site URL to `https://taiwen.vercel.app` and allow `https://taiwen.vercel.app/auth/callback`. For local testing, also allow `http://localhost:3000/auth/callback`. Do not use taiwen.vn.
3. Enable Google in Supabase Authentication → Providers. Configure a Google OAuth web app with the Supabase callback shown in the Google provider settings (normally `https://<project-ref>.supabase.co/auth/v1/callback`). Store the Google client ID and secret in Supabase only.
4. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in the existing Vercel project for Production (and in ignored `.env.local` for local testing). Redeploy through the existing GitHub `main` workflow. Never use a service-role/secret key in a `NEXT_PUBLIC_` variable.
5. Configure a Meta app and the Facebook provider in Supabase. The Meta redirect URI is the Supabase callback shown in the Facebook provider settings. The Facebook button appears only when Supabase reports that provider as enabled; no provider secret belongs in Vercel or browser code.

After OAuth, the learner reaches `/account`. Account progress is separated by the verified Supabase user ID and synced to the protected tables. Existing guest `localStorage` data stays in place. The learner can explicitly choose **Gộp tiến độ khách**; the guest copy is preserved. Repeating the import updates records with the same stable IDs. On a concurrent edit, the learner chooses the cloud or device version in the account page; the importer does not silently overwrite either version.

If Supabase or the network is unavailable, the per-account local copy remains on the device and pending changes are retried when the app opens again or reconnects. The exam's persisted absolute deadline stays authoritative during refresh/resume; the one-second display tick does not write to the database. Cloud progress is not ready for real accounts until the SQL migration and environment variables have been applied.

Before announcing OAuth as live, use two separate test accounts to verify Google and Facebook sign-in, logout, guest merge confirmation, and cross-device resume. Under user A's session, attempt to select, update, and delete user B's rows in `profiles`, `progress_documents`, `vocabulary_progress`, `learned_vocabulary`, `personalized_vocabulary_sets`, `test_attempts`, `practice_annotations`, and `activity_progress`; each attempt must return no rows or an RLS error. Repeat with the users reversed. Never use a service-role key for this check, because it bypasses RLS.

Academy owner editing uses an additional migration and explicit editor allowlist. See [Academy navigation and content](../docs/academy-navigation.md) before enabling the editor.
